# 同城徒遇原型与开发说明

版本 2.0 ｜ 审查修订日期 2026年11月5日

本次交付只有两个必要文件：`index.html` 与 `README.md`。index.html已内嵌Bootstrap 5.3.3、全部自定义CSS、JavaScript、SVG图标和两张真实户外摄影，不依赖app.js、styles.css、assets目录、CDN、字体服务或其他文档。双击index.html即可使用；不需要安装、构建、联网或服务器。

它是具备真实本机状态联动的高保真交互原型，可作为iOS界面和前端开发参考，不是已接入真实GPS、Apple登录、云端社区、推送或审核人员的生产App。所有“演示审核”和“公开”均只改变当前浏览器内的数据，不会向任何人发布、报名或发送消息。

## 1 本次已直接修复的问题

1. README文件结构与实际单文件交付不一致：改为只说明index.html和README.md。
2. 仅计时仍显示GPS和固定距离：计时模式不再显示地图、GPS、距离数据，也不会增加护照累计距离。
3. 选择只变样式：节奏、筛选、列表分组、月历选日、作品状态、关注与收藏均真实驱动页面数据。
4. 复盘单选未提交、标题保存未实现：表单改为具名radio与字段，修改后在详情、列表和档案中复用。
5. 分享照片与开关未带入预览：本机照片会缩放并重编码，再保存在草稿；预览和作品只包含选择公开的摘要与心得。
6. 活动状态、名额和集合权限不联动：报名通过占位，退出释放名额，退出后详情和公告收回受限信息；本机双重提交有状态检查。
7. 审核只有成功路径：增加报名拒绝、作品未通过与下架、活动未通过及修改后重提，审核与时间状态分离。
8. 记录刷新丢失：持续保存，刷新后暂停，提供恢复入口，不补算关闭期间的数据。
9. 删除只清空部分字段：行程删除联动统计与合集引用，账户删除同时清空数据并停止计时。
10. 消息跳错对象：消息保存关联活动、行程与作品ID，跳转时恢复对应对象。
11. 图像绝对定位和卡片裁切异常：补齐inset和宽高；两张摄影均内嵌可加载，明确不冒充杭州路线实景。
12. 安全区和触控尺寸不足：桌面固定模拟画布，小屏使用dvh及env安全区；按钮和筛选标签至少44px；确认操作用原生dialog并支持取消。

## 2 用户体验与核心路径

底部唯一顺序为「广场 → 约行 → 记录 → 徒步 → 我的」。广场负责发现与作品，约行负责同行关系，记录负责历史、复盘和护照，徒步负责当前行程，我的负责管理。默认启动广场，私人行程不自动公开。

### 路径一 先选节奏再同行

约行 → 节奏标签（不限／轻松慢走／边走边拍／稳定行进）→ 活动详情 → 申请同行 → 登录（未登录时）→ 报名申请 → 报名结果 → 演示审核结果 → 查看活动详情 → 关联并开始徒步。

登录成功回到原操作，不要求重新找活动；申请提交不占位，通过后才占位。活动详情中仅已通过成员及发起人看到详细集合点和公告。所有演示审核入口明确标注“演示”或“模拟”，正式App须由真实后台授权。

### 路径二 一条行程留下三种成果

徒步 → 开始示例徒步或仅计时模式 → 标记片刻 → 结束本次徒步 → 结束并保存 → 完成总结 → 一分钟复盘／生成山野分享卡 → 公开范围预览 → 提交内容审核 → 作品审核状态。

行程自动进入记录、月历与护照；复盘可跳过；分享须主动选择公开字段。三个出口复用同一条行程数据。差异化来自“节奏对齐”和“一条记录多种成果”，并非已验证的市场独占能力。

## 3 浏览方式与画布安全区

- 左侧「交互预览」显示当前页面；「全部界面」显示50个手机画框，每个内容区独立滚动。点击总览中的页面按钮返回单页模式。
- 目录名称、页面头部名称及下表名称来自同一页面注册表；用`#路由名`可直接访问。顶栏「返回」优先回到实际上一页面，没有历史时采用代码中的指定回退页。
- 桌面与总览的画框为402×874 CSS像素，参考iPhone 17 Pro的1206×2622物理像素按3倍换算。圆角54px，模拟顶部安全区62px，底部34px，Tab操作区56px。这些是原型参考值，不宣称是所有系统状态下的真实safeAreaInsets。
- 普通详情内容距底部34px；一级页距底部56+34=90px；带固定活动操作区的详情预留88+34=122px。固定操作区和Home条不遮住滚动内容。
- 430px及以下的单页模式视为真实手机浏览器：不重复绘制硬件状态栏、动态岛和Home条，不再画设备外框；顶部工具区128px，App占余下的`100dvh - 128px`。内容顶部使用`max(12px, env(safe-area-inset-top))`，底部使用`max(16px, env(safe-area-inset-bottom))`。这不是把完整874px画框压进剩余空间。
- 小屏总览仍显示402×874参考画框，窄于402时宽度适应容器，允许逐个审阅；实际开发始终以系统布局和安全区域为准。
- 表单聚焦使用浏览器原生滚动与键盘避让；真实Safari键盘、系统悬浮栏及原生锁屏记录仍需真机验收，不能由桌面截图证明。
- 苹果尺寸来源：https://support.apple.com/en-us/125090 。布局参考：https://developer.apple.com/design/human-interface-guidelines/layout 。

## 6 页面按钮与跳转契约

本节从14组状态快照的实际渲染结果生成：首次访问、已登录与待审报名、报名通过与作品、发起人与报名管理、活动审核与计时、轨迹与合集、未通过、已公开与取消、下架与收藏、恢复与草稿、名额已满、活动截止、活动取消、数据清空。相同按钮在不同状态下可能不出现，不代表它不存在。

公共交互：五个Tab跳转到同名一级页；目录跳转到注册路由；「返回」弹出页面历史，没有历史则使用页面指定回退路由。日期按钮选择当天行程，上个月／下个月改变月历。活动、行程、作品、合集、复盘条目和消息卡片的完整文字来自数据，其点击行为见下表。所有动态文字均转义，避免把用户输入当作HTML执行。

|卡片类型|点击结果|
|---|---|
|活动卡片 `activity:ID`|选中该活动 → 活动详情 `#activity`|
|行程卡片 `trip:ID`|选中该行程 → 行程详情 `#journal`|
|作品卡片 `post:ID`|选中该作品 → 作品详情 `#post`|
|合集入口 `collection:ID`|选中该合集 → 主题合集 `#collection`|
|复盘入口 `reviewtrip:ID`|选中该行程 → 一分钟复盘 `#review`|
|报名管理入口 `manage:ID`|选中自己的活动 → 报名管理 `#manage`|
|消息卡片 `message:ID`|标记已读，恢复关联对象 → 消息存储的目标路由|

`go:名称`为直接跳转；其他事件由后面的状态协议解释。事件中的`owned`和`r1`为审查快照的对象ID示例，实际运行使用对应活动或申请的动态ID，不能硬编码。表单的提交按钮记作`submit`，实际结果见下一节。以下保留代码里的按钮原文，不用近义词替代。

## 7 表单提交与保存规则

所有文本提交会去除首尾空格，必填字段不能只输入空格；失败在表单内显示错误并保留输入。下面名称与HTML的`data-form`一致。

|表单|字段及限制|成功后的唯一结果|
|---|---|---|
|apply|经验与节奏单选；说明最多200字；必须勾选成人与规则确认；需登录且活动可报名|保存待审核申请 → 报名结果；不占名额|
|city|城市名称必填，最多20字|保存城市 → 约行；无数据城市显示空状态|
|filter|日期、距离、节奏、只看可报名|保存实际查询条件 → 约行；重置筛选清除全部条件|
|create|标题及路线各30字；城市20字；日期时间必填；距离0.1至100km；爬升0至5000整数；人数2至12整数含发起人；区域50字；详细点100字；路线1000字；装备500字；成人确认必勾|保存活动为待审核 → 活动审核状态；修改重提更新原活动|
|notice|公告内容必填，最多500字；仅发起人且活动未取消|保存公告，刷新当前活动公告与问答|
|question|集合／时间／装备／节奏；问题必填最多200字；需通过报名或发起人|保存问题，刷新当前页|
|answer|回复必填最多200字；仅该活动发起人|保存回复，刷新当前页|
|review|体感与节奏单选；装备300字；提醒200字|保存到选中行程 → 行程详情；复盘档案同步|
|rename|行程标题必填，最多30字|更新实际标题 → 行程详情；列表同步|
|collection|标题必填最多20字；多选实际行程；公开开关；空合集不能公开|新增或更新同一合集 → 主题合集|
|marker|标记类型单选；文字必填300字；可选本机照片；需有进行中记录|保存到当前行程 → 徒步进行中|
|publish|模板单选；标题必填30字；正文1000字；封面；有行程时可选摘要与心得|保存草稿 → 公开范围预览；尚未提交审核|
|profile|昵称与城市必填各20字；简介200字；节奏单选|保存 → 我的；自己的作品作者名与活动发起人名同步|

活动时间：开始晚于当前，结束晚于开始，截止在当前与开始之间。每人同时最多一个未结束且未取消的有效活动，未通过活动允许修改重提。所有时间按浏览器当地时区输入、以ISO保存并按当地时区显示。初始示例活动相对首次打开日期生成，不硬编码已经过去的周末日期。

活动草稿和分享草稿在输入时保存。照片必须是浏览器能解码的图片且不大于10MB，最长边缩至1000像素，再转为JPEG；保存的是解码后的图像，不是含位置元数据的原始上传文件。草稿、预览和作品使用同一张处理后的封面。

浏览器容量用尽或禁用localStorage时不会谎称已持久保存：提示“本机存储不可用，更改仅保留到关闭页面前”，界面显示持续提示。本机存储的可用容量取决于浏览器。

## 8 状态变化与操作协议

### 约行与权限

- `join`：校验可报名，未登录跳到登录，成功后回报名申请。`auth:路由`同样记录登录回跳目标；`cancellogin`回到触发页。
- `loginfrommine`、`login`、`logout`：进入或退出本机演示账号；退出不删除本机私人行程，不停止正在计时的记录。
- `demoapproval`打开“模拟通过报名”确认框，确认执行`approve`；待审核不占位，通过占1位；满员、截止、取消或被屏蔽时不能新通过。`rejectapplication`将待审报名改为未通过，同活动不重复申请。
- `withdraw`／`leave`打开确认框，`withdrawconfirmed`撤回或退出，已通过时释放名额并立即隐藏受限信息；退出后截止前可再申请。
- `newactivity`先登录再去发布；`approveactivity:ID`模拟活动通过；`rejectactivity:ID`给出未通过原因；`editactivity:ID`将该活动全部字段带回表单重提。真实审批必须在服务端。
- `samplerequest`仅向自己招募中的活动加入一条明确的示例报名，`request:accept:ID`通过并占位，`request:reject:ID`拒绝。达到上限不能继续通过；没有自由群聊或私信。
- `cancelactivity`打开“确认取消约行”，`cancelconfirmed`关闭报名并生成站内取消消息。公告页会提示取消，不再接受新问题。
- 集合详情只对发起人和已通过成员显示。屏蔽不静默移除已有约行关系，保留退出入口；阻止新增报名并隐藏对方公开作品。
- 时间状态依次考虑取消、审核中／未通过、已结束、进行中、截止、满员、招募中。待审核活动不出现在公开列表。没有商业带队、付款、自动路线规划或救援承诺。

### 记录与成长

- `start`开启示例轨迹模式，固定示例距离3.28km且明确标注；`timeronly`开启仅计时，不包含距离或地图；同一时间只能有一条进行中记录。
- `pause`在暂停与继续间切换，暂停不累计用时。计时使用真实时间差而不是把每次回调当作一秒；`resume`从最后保存点恢复，刷新或关闭期间不补算。
- `finishrecord`只保存一次当前行程、停止计时、进入完成总结；没有进行中记录时显示空状态，不生成假行程。
- `linkpicker`去我报名的约行；在已通过活动详情点`linkhike`关联行程。未通过不能关联。
- `recordtab`、`day`、`month`实际改变行程／月历／合集内容；统计来自现存行程，活动天数按开始日期去重；仅计时不增加距离。
- `newcollection`创建空白合集；`deletecollection`确认后执行`deletecollectionconfirmed`，不删除原行程。
- `deletetrip`确认后执行`deletetripconfirmed`，删除行程并更新月历、统计、合集引用；作品保留已确认公开的快照并断开源行程引用；未提交草稿不再引用被删行程。

### 分享与社区

- `newpost`继续已有草稿或创建普通图文；`sharetrip`从行程生成关联草稿，需登录；普通图文不凭空附加距离。
- 模板为“照片故事”“路线回忆”“极简成绩”。模板名称和标识会改变，但不改变事实数据；当前不提供海报图片导出按钮。
- 公开摘要关闭时，预览和作品均不显示距离与用时；心得关闭时不显示提醒；两项开关独立。轨迹、起终点、集合点与同行者身份始终不进入作品数据。
- `publishpost`生成待审核作品快照并清空已提交草稿，进入作品审核状态；`approvepost`模拟公开并加入广场，`rejectpost`给出未通过原因，`removepost`模拟下架并从广场移除。
- `editpost`从本人未通过或下架作品带回标题、封面、正文和公开选项，重提后替换原作品为待审核；`deletepost`确认后执行`deletepostconfirmed`，不影响行程。
- `like`、`favorite`、`follow`真实更新本机列表；“关注”广场只显示已关注作者，“我的收藏”只显示实际收藏。`block`屏蔽当前作者，`unblock:ID`解除。
- `feed`、`workstab`、`mytab`、`managetab`、`messagetab`切换实际数据分组，不是只变颜色。自己的审核中、未通过、下架作品不会进入公开广场。

### 账户与通用状态

- `readall`保存所有消息已读状态；消息保存对象上下文，点击不会跳到上一次随意查看的其他活动。
- 活动通知偏好开关保存本机设置，不请求系统通知。所有通知是本机事件，原型不使用APNs。
- `deleteaccount`先检查勾选，再打开“确认删除演示账户”；确认执行`deleteconfirmed`，清空账号和全部演示数据，停止计时，不恢复示例行程。
- `reset`打开“确认重置演示数据”；确认执行`resetconfirmed`，恢复初始样例并停止计时。两种行为不同，均可点“暂不操作”或Esc关闭dialog。
- `noop`只用于禁用操作，没有可点击的假按钮。未知路由返回广场并给出提示。
- 空白、离线、错误、恢复、加载页都有明确下一步。离线页不会声称存在尚未实现的同步队列；加载页是可查看的状态样例，“查看加载完成”回广场。

## 10 开发接入边界

页面注册表`pages`是路由和名称的唯一来源；`frame`管理安全区与底栏；`db`是本机业务数据，`ui`是临时视图状态；`action`处理按钮，`onSubmit`处理表单。状态保存在`localStorage`的`tuyu-reviewed-v2`键，不读取或覆盖旧版本键或其他站点数据。这个键不是安全存储，不应放入敏感身份资料。

正式实现需把本机仓储替换为受鉴权的服务：活动列表及筛选、报名与名额原子更新、公告、作品审核、举报、屏蔽、通知、账号删除。原生层负责Core Location、MapKit或合法地图服务、PhotosPicker、AuthenticationServices、UserNotifications与本地数据库；不能把网页示例轨迹当成已完成的GPS模块。

约行名额的本机校验只能防止单实例重复操作，不提供多人并发、跨设备或服务端授权保证。集合信息在当前原型中只是UI可见性限制，不能作为真实隐私边界；正式服务必须按每次请求鉴权。真实推送、照片审核、后台锁屏采集、业务持久化、成年用户验证和运营审核均未接入。
